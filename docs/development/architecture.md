# 平台架构与依赖约束

规范版本：2026-11-14.1。约束沿现有工程职责制定，不要求为“分层”增加服务、队列、平台或无意义目录。

## ARCH01 现有模块职责

| 位置                                          | 职责                                      | 不能承接                                   |
| --------------------------------------------- | ----------------------------------------- | ------------------------------------------ |
| apps/web                                      | 页面、草稿、查询与事件展示，消费共享契约  | 最终授权、批准、数据库访问或秘密解密       |
| apps/api                                      | HTTP、官方 MCP、文件入口与应用组合根      | 复制另一套业务规则或以请求参数授予身份     |
| apps/ai-worker                                | AI 任务、模型适配、受控工具编排与调用事实 | 远程唤醒用户 Ego、绕过授权或重放未知业务   |
| apps/api-worker                               | 受控接口执行、步骤与清理运行事实          | 任意 SQL、无限制脚本或自动重试被测请求     |
| packages/contracts                            | Schema、类型、协议、枚举和公开错误语义    | React、Nest、存储驱动、实例文件和秘密      |
| packages/application                          | 业务规则、对象授权、状态、版本与事务编排  | 反向依赖 apps、任意宿主能力或独立权限副本  |
| packages/persistence、storage、model-adapters | 各自持久化、字节存储与模型协议边界        | 反向导入应用入口或接管其他模块业务         |
| tooling/local-client                          | 可独立构建的客户端、契约与受信端口        | 在运行时初始化整个平台或读取宿主私密配置   |
| deploy、scripts                               | 明确分类的构建、启动、运维及开发工具      | 隐藏实例绑定、混入产品的测试或自动执行部署 |

## ARCH02 依赖方向

运行入口组装依赖，应用服务执行规则，契约描述边界，基础设施提供相应能力。

- Web 不导入后端应用服务、数据库、存储或模型适配器。
- contracts 不反向依赖应用、框架和驱动，也不读取环境配置。
- application 不依赖 apps；持久化、存储、模型协议层不反向导入应用入口。
- 纯类型端口与运行时实例化分开审查。现有 Database 等类型位于既有包中，不因包名机械认定越层；但不得借类型引用初始化连接或引入运行副作用。
- 应用服务现有的数据库端口和事务模式继续使用；不为通过规范另起全套 repository 或微服务。数据写入由负责该业务的服务组织，不跨模块随意更新他表。
- 不把源码相邻或 TypeScript 能 import 当成允许依赖的理由。新增包、跨层调用、循环依赖或例外须说明职责、替代方案与影响。

目前没有自动全库架构门禁。评审须检查新增 import、运行时依赖及模块闭环；typecheck 通过不能代替此项，也不能声称已穷尽文件级循环。

## ARCH03 入口和副作用

- controller、MCP handler 和 UI 发送领域意图，业务服务执行当前对象权限、基准、状态与幂等检查。
- Web、平台内部工具、官方 MCP 共用服务但暴露面不同，不能为了“统一”增加不开放的管理工具。
- 事务不跨模型、HTTP 或对象存储长时间持锁；外部副作用保留原命令、发送意图和结果确定性，不能统一套重试。
- 可复用库导入无网络、部署、数据库初始化、秘密读取或业务写入。执行动作置于明确入口或工厂，依赖从入口注入。

## ARCH04 构建和独立组件

- [运行构建](../../tsconfig.server.json) 显式列出应用及必要运行工具；[开发构建](../../tsconfig.tools.json) 输出到被忽略的 .local-build/tools。
- [服务端构建器](../../scripts/build-server.mjs) 校验固定输出根并清理旧 dist。不得恢复宽泛 scripts include，把历史 helper 自动编入运行包。
- 本地 client 用自己的 package.json 和 --ignore-workspace 构建，不能靠平台 dist 中的旧产物或本机绝对路径运行。
- 平台 quality:check 额外调用 quality:client，按独立 client 的 tsconfig 做类型检查；打包仍走其自身明确入口。
- 三个 Skill 通过自身固定契约及注入的可信端口集成，不运行时跨仓库 import。规则共享不代表共享秘密或放开权限。

Windows 平台命令可使用现有 deploy/local/Invoke-Pnpm.ps1 包装器；它使用已安装的项目 pnpm，不另行安装或下载一个 latest。
