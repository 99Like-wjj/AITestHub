# Office browser runtime

The office browser is separate from platform UI test execution. It cannot publish a test verdict, grant a platform approval, or wake a user's local Ego browser. Page text, screenshots and DOM labels are untrusted source data.

The application injects `BrowserBrokerClient` from `AITESTHUB_BROWSER_ORIGIN` and `AITESTHUB_BROWSER_TOKEN_FILE`. Only the API and AI worker receive this restricted broker credential. A separate proxy credential belongs only to the browser broker and its egress proxy; profiles, cookies, storage and raw CDP are not exposed to application tools.

Use the exact Playwright dependency and matching browser image. `Dockerfile.browser` copies the verified application Node binary and dependencies because the upstream browser image has its own Node version. The application artifact and browser runtime must be built from the reviewed source. `compose.browser.yaml` is a portable template; instance addresses, token files and persistent journal paths belong in external configuration.

The browser container attaches only to the internal control network. The proxy also has an egress network. Attach the trusted API/worker to the control network while retaining their existing required networks. Keep the browser off the default internet network. Do not use host networking, privileged mode or a Docker socket for the browser.

Both runtimes require a reviewed JSON network policy with an exact SHA-256 binding: `AITESTHUB_BROWSER_NETWORK_POLICY_FILE` and `AITESTHUB_BROWSER_NETWORK_POLICY_SHA256`. Populate `forbiddenOrigins` with all current platform, broker and control origins. These are blocked by resolved address and port as well as name. Metadata/link-local addresses cannot be enabled by a private allowlist. `allowedPrivateOrigins` grants network reachability to exact origins; it does not supply credentials or business permissions. `allowedWebSocketOrigins` supports only explicitly configured WSS sources. Unconfigured sockets and client frames outside a human/approved action window are blocked and reported.

The browser broker entry point is `dist/packages/agent-browser/src/main.js`; the proxy entry point is `dist/packages/agent-browser-proxy/src/main.js`. Browser configuration additionally includes `AITESTHUB_BROWSER_JOURNAL_DIRECTORY`, `AITESTHUB_BROWSER_PROXY_CONTROL_ORIGIN` and `AITESTHUB_BROWSER_PROXY_TOKEN_FILE`. Proxy configuration includes `AITESTHUB_BROWSER_PROXY_ORIGIN` and its token file. Bind addresses and ports default to loopback; deployment supplies private container bindings explicitly.

Each account/conversation uses a separate BrowserContext. Public navigation is read-only; page-initiated submissions are blocked. Existing human login state is readable by AI only in the trusted full-access scope. Finite interaction plans bind exact observations, expire, and require a genuine owner Web decision. The broker consumes operation IDs in its persistent journal before acting. Unknown results are reconciled with the original ID, never executed under a replacement ID.

Manual control suspends AI access. Secret input is sent only to the selected page control and is omitted from database operations, snapshots, model arguments and journals. Inputs, editable regions, canvas and video are masked in screenshots. A known secret echoed by a page prevents sharing. Closing the context clears its login state; lost contexts are not silently recreated with old credentials. The worker must call `AgentBrowserService.reconcile()` to close expired, deleted or deactivated owners' original contexts.

`browser-seccomp.json` adapts the upstream Microsoft Playwright v1.65.0 profile under Apache-2.0; the adjacent license preserves its terms. It adds only the `chroot` syscall needed inside Chromium's user namespace while retaining nonroot execution, dropped outer capabilities, no privilege escalation and Chromium sandboxing. Docker isolation shares the host kernel and is not a virtual machine.

Office browser receipts describe actual browser actions and observed data. A returned click or HTTP response is not a business success, test acceptance, review approval or proof of compatibility with every office website. Downloads, arbitrary uploads, popups and Service Workers remain disabled; applications that require additional network behavior must be reviewed and tested explicitly.
